# AI 对话自动联网功能规划

状态：首期已实现，完成离线验证；真实服务验收待执行。更新日期：2026-09-30。

已确认的需求是：由 AI 自动判断当前问题是否需要联网。本文记录首期设计、当前实现和启用前的验收要求。按本次确认的范围，只实现功能并进行离线验证，不调用真实模型或 Tavily；文中的质量、延迟和费用指标仍是待实测目标。

项目尚未上线，前后端按同一套新契约开发和同步发布，不增加旧客户端、旧请求格式或历史版本指纹的兼容分支。

首期交付“自动判断 → 有界搜索 → 带来源回答”，覆盖普通对话和学习问答。复用现有聊天生命周期、上下文管理和消息组件，完成来源可追溯、取消可靠、历史可恢复的流程。接入配置和离线复核入口见第 11 节。

## 1. 确定首期范围

| 范围                   | 首期行为                             | 边界                                         |
| ---------------------- | ------------------------------------ | -------------------------------------------- |
| 普通对话、节点学习问答 | `kind=qa` 支持自动联网               | 联网只补充依据，沿用当前回答风格             |
| 联网控制               | 后端统一自动判断，前端不提供联网开关 | 后端总开关关闭后不执行联网决策和搜索         |
| 自动判断               | 结合当前问题和必要上下文决定是否搜索 | 不只依赖“最新、今天”等关键词                 |
| 信息检索               | 接入一个搜索服务，最多两个查询       | 优先使用返回的相关内容片段                   |
| 来源展示               | 正文引用、来源列表、检索时间         | 搜索片段不能标记为“已阅读全文”               |
| 聊天操作               | 支持停止、重试、重新生成、刷新恢复   | 与原有请求和消息生命周期一致                 |
| 主题及节点概览         | 保持当前生成流程                     | `topic_overview`、`node_overview` 不触发联网 |
| 独立学习 Agent         | 保持当前评估、计划流程               | 界面明确联网设置不作用于这些流程             |

指定网页全文读取、多轮深度研究、浏览器操作、文件下载、多个搜索服务自动切换放入后续迭代。首期不引入向量数据库或新的任务队列。

### 判断示例

| 输入                         | 预期判断                                 | 验收关注点                       |
| ---------------------------- | ---------------------------------------- | -------------------------------- |
| “解释一下递归”               | 通常不搜索                               | 稳定知识避免不必要搜索           |
| “帮我修改下面这段代码”       | 根据材料直接处理；涉及新版本接口时再判断 | 不能将所有代码问题一律判为不搜索 |
| “某框架最新版本有哪些变化”   | 搜索，优先官方资料                       | 时间范围与版本匹配               |
| “推荐近期适合入门的学习资源” | 搜索                                     | 返回真实、相关的资源链接         |
| “这个说法有依据吗”           | 结合上一轮确定待核实说法                 | 不搜索无意义的指代词             |
| “那它现在还适用吗”           | 补全对象后判断时效需求                   | 多轮指代与时间要求同时保留       |
| “只根据我提供的材料回答”     | 不搜索                                   | 尊重用户限定的资料范围           |
| 仅提供 URL 并要求总结全文    | 明确首期不支持直接读取全文               | 不将搜索摘要冒充已读取的网页     |

## 2. 沿用现有能力

以下是实现前的复用分析，实施后仍沿用这些入口；新增服务及组件见第 11 节。

| 现有证据                                                                                                            | 设计判断                                 | 实施路径                                                       |
| ------------------------------------------------------------------------------------------------------------------- | ---------------------------------------- | -------------------------------------------------------------- |
| [聊天路由](../backend/routers/chat.py) 已处理请求 ID、SSE、重放及取消                                               | 联网属于同一轮聊天的准备阶段             | 扩展原 `/api/chat/stream`，保留既有终态协议                    |
| [模型调用](../backend/ai/agent.py) 当前处理文本流，未实现工具调用循环                                               | 通用模型的首期接入适合由后端控制搜索步骤 | 先做结构化决策，再调用搜索服务和现有回答模型                   |
| [结构化 AI 服务](../backend/services/agent/structured_ai.py) 已有 JSON 校验、一次修复及 usage 记录                  | 可以复用，需补充调用预算参数             | 为决策配置独立超时、输出上限和修复次数，保留其他调用者默认行为 |
| [上下文组装](../backend/services/chat_context.py)、[预算计算](../backend/core/context_budget.py) 已统一控制最终输入 | 检索证据必须参加同一预算计算             | 组装前分配证据预算，发送前再次校验完整消息                     |
| [轮次生命周期](../backend/services/chat_lifecycle.py) 已有指纹、租约、内容版本及取消记录                            | 无需新增一套聊天状态机                   | 所有联网阶段复用同一轮次及受保护写回                           |
| [消息模型](../backend/models/progress.py) 已提供 `metadata_json`                                                    | 首期可直接存有限来源快照                 | 定义带版本的 `web` 子字段，暂不新增检索表                      |
| [聊天主组件](../frontend/src/components/SocraticDialogue.vue) 共用 `streamDialogue`                                 | 普通问答和学习问答可共用联网入口         | 扩展请求快照及回调，沿用会话隔离和迟到事件保护                 |
| [消息列表](../frontend/src/components/dialogue/MessageList.vue) 存在 `v-memo`，未包含来源依赖                       | 仅更新 metadata 可能不刷新来源           | 加入来源版本或不可变对象依赖                                   |
| [Markdown 渲染](../frontend/src/components/dialogue/InlineMarkdown.vue) 使用 `marked.parse` 与 `v-html`             | 引入外部资料需要补齐 HTML 净化           | 复用渲染组件和流式节流，增加净化及安全链接处理                 |

采用“决策模型 + 独立搜索服务”的优点是对现有自定义模型依赖较少，搜索次数和成本容易限制；缺点是即使最终不搜索，自动模式也可能增加一次模型往返，且需要自行维护引用协议。后续可以在能力明确的模型上增加原生工具调用适配器，但业务层继续使用统一来源结构。

## 3. 组织一轮自动联网请求

1. 校验用户、会话、主题、模型和请求参数，通过 `begin_chat_turn` 获取会话所有权并保存消息占位。会话忙或请求重放时不启动新的联网调用。
2. 复用当前上下文预检，确保问题、明确引用和必要历史可处理。已有摘要整理逻辑继续生效，不为决策或检索静默丢弃对话。
3. 返回 `msg_ids`。对 `qa + auto` 且服务可用的请求发送决策状态；关闭模式直接进入普通回答。
4. 从已校验上下文中提取当前问题、必要近期对话、学习主题及当前日期，执行一次受限的结构化决策。明确限定资料范围时不搜索；指代无法确定时不编造查询对象，可以先回答澄清问题。
5. 需要联网时执行搜索，按相关性去重、限制来源数和片段长度，生成本轮稳定来源 ID。搜索期间不持有数据库长事务。
6. 将决策、检索状态、来源快照通过受保护的短事务写入当前 AI 消息；将证据纳入上下文并重新计数，再调用现有回答流。
7. 输出正文、校验引用映射，通过同一受租约保护的事务提交正文、最终联网快照和聊天终态；重新生成时在该事务内替换旧答案。提交成功后发送最终来源快照，再沿用 `request_state` 和 `[DONE]` 结束本轮。

每阶段开始、结束及长时间等待期间都需要检查取消、内容版本和租约。首期只执行一次搜索批次；检索不足时说明缺少依据，不自动进入无限追加搜索。

### 决策契约

`SearchDecision` 使用严格 schema，拒绝多余字段。下例是服务内部结构，不是独立 API：

```json
{
  "need_search": true,
  "queries": ["Vue 官方 最新版本 发布说明"],
  "freshness": "month",
  "reason_code": "current_information"
}
```

- `queries` 最多两个，每条限定长度；需要搜索时至少一个，不搜索时必须为空。问题通常使用一个查询，只有确需独立证据时使用第二个。
- `freshness` 为 `any/day/week/month/year`；时效筛选是否适用取决于问题，不把所有联网请求都限制为近期资料。
- `reason_code` 为 `stable_knowledge/current_information/verify_claim/find_resources/explicit_search/user_restricted/insufficient_context/unsupported_url_fetch`，仅用于状态与观测，不保存或展示模型内部推理。
- 后端总开关关闭、服务不可用、非问答类型属于后端规则，模型不能覆盖。网页内容也不能改变本轮搜索额度和策略。
- 默认沿用用户本轮所选模型。后续如增加专用决策模型，需显式配置和评估，不暗中切换到未配置的服务。

复用 `generate_structured` 时，将超时、输出预算及允许修复次数作为可选策略参数；避免复制另一套 JSON 调用逻辑，也避免沿用当前固定 60 秒等待。决策输出预算必须兼容推理模型的生成开销；不支持温度参数的模型仍按已有模型配置处理。

### 搜索适配器

业务层只依赖 `SearchProvider` 的统一请求、结果和错误结构；Provider 实现负责服务商字段转换。首期使用已有 HTTP 依赖和可复用连接池，限制并发、连接数、响应体积和总等待时间。

首个适配器为 Tavily。其搜索接口提供标题、URL、相关内容片段，以及时间、域名等筛选参数；实现使用 `search_depth=basic`、`include_answer=false`、`include_raw_content=false`、`include_usage=true`，由当前回答模型统一组织回复。[Tavily 官方接口文档](https://docs.tavily.com/documentation/api-reference/endpoint/search)

该选择仍需以部署环境连通性、中文样本质量、片段对答案的支持程度和实际费用验证。本文不承诺服务商响应时延或固定价格；首次评估不通过时可替换适配器，无需改前端协议。

## 4. 约定请求、事件与存储

本节是当前首期契约。前后端已同步调整请求类型、调用点和事件解析，不引入旧客户端兼容层。

### 请求与能力发现

`POST /api/chat/stream` 不接受前端指定 `web_mode`，由后端统一管理：

- 后端按 `kind` 派生内部策略：`qa` 固定为 `auto`，概览固定为 `off`，搜索是否可用继续受服务端 `.env` 总开关与凭据控制。
- 前端不展示联网模式选择及输入栏的能力提示，不保存会话联网偏好；普通发送、重试和重新生成都不传联网模式。
- 请求携带 `web_mode` 会作为多余字段返回参数错误。项目尚未上线，不保留旧参数兼容层。
- 重新生成使用新请求 ID，由后端按请求类型重新判断；同请求重放仍使用保存的结果和来源。

需要登录的只读 `GET /api/chat/capabilities` 返回 `{"web_search":{"available":false,"mode":"auto"}}` 等诊断信息，不返回密钥、服务商配置或内部错误详情。输入栏不再调用该接口；实际调用由后端检查能力。

联网总开关关闭或搜索凭据不可用时，后端为自动问答发送明确的非终止警告，在回答处显示并按降级规则处理，不能伪装成成功搜索。

### SSE 事件

保留现有 `msg_ids/text/request_state/error/[DONE]`，只增加下列事件。`request_id` 和 `ai_message_id` 用于关联本轮消息，前端仍需验证当前会话和 stream epoch。

| 新事件        | 内容                                                              | 前端行为                               |
| ------------- | ----------------------------------------------------------------- | -------------------------------------- |
| `web_status`  | `deciding/searching/ready/skipped/failed/unavailable`，可附来源数 | 显示检索进度，失败不自动结束正文流     |
| `web_sources` | 来源候选快照、已引用 ID、`final` 标记                             | 更新来源映射；最终快照替换临时候选展示 |
| `web_warning` | 稳定错误码、用户文案、是否可重试                                  | 显示未核实或部分结果提示，继续受控回答 |

事件精简示例（实际事件还包含完整 `web` 快照）：

```json
{
  "type": "web_status",
  "request_id": "web-plan-example-1",
  "ai_message_id": 42,
  "status": "searching"
}
```

搜索结果准备好后可发送 `final=false` 的候选快照。正文完成后解析实际引用，持久化并发送 `final=true` 的来源快照，再发送 `request_state.status=complete` 与 `[DONE]`。当前前端在收到完成状态时结束处理，因此来源不得放在完成事件之后。

搜索异常可恢复时使用 `web_warning`，不能复用现有会终止流的 `error`。取消、租约丢失、上下文失效或最终回答失败仍沿用聊天错误及终态协议。重放必须在终态前补发保存的联网状态和来源；未执行检索的问答保存对应状态，前端不显示空来源列表。

`WEB_EVIDENCE_TRUNCATED` 表示服务端按上下文预算缩短或省略了片段，保留在快照与内部回答约束中，但前端不展示该技术提示。搜索失败、证据不足等影响回答可信度的提示仍展示；来源列表与引用不受影响。

### 消息元数据

当前 AI 消息的 `metadata_json.web` 存放有版本的快照。下例中的内容和链接仅用于说明结构，省略了 `strategy_version/config_version/warnings/metrics` 字段：

```json
{
  "schema_version": 1,
  "requested_mode": "auto",
  "status": "ready",
  "decision": {
    "need_search": true,
    "reason_code": "current_information",
    "freshness": "month"
  },
  "queries": ["示例工具 官方 发布说明"],
  "searched_at": "2026-09-30T16:00:00Z",
  "sources": [
    {
      "id": "s1",
      "title": "示例工具发布说明",
      "url": "https://example.com/releases",
      "domain": "example.com",
      "excerpt": "示例片段，仅说明字段用途。",
      "published_at": null,
      "retrieved_at": "2026-09-30T16:00:00Z"
    }
  ],
  "cited_source_ids": ["s1"],
  "error_code": null
}
```

规则：

- 持久状态使用 `off/skipped/deciding/searching/ready/failed/unavailable`；是否完整回答仍以 `ChatTurn.status` 为准。检索成功不等于回答成功，`ready` 也不保证一定存在引用。
- 来源 ID 在当前 AI 消息内唯一且固定，跨消息通过“消息 ID + 来源 ID”定位；不能用全局的 `[1]` 判断是哪一轮资料。
- 来源只存有限片段和元数据，不存网页全文。查询及片段按会话权限访问，原始查询默认不写入普通日志。
- 发布时间允许为空，检索时间不能冒充发布时间。抓取时间新也不代表页面内容新。
- 所有写回合并既有 metadata，并验证请求所有权、generation token、内容版本和取消状态。删除及归档沿用现有消息处理路径，并补测来源不会丢失或被迟到任务恢复。
- 来源快照复用 JSON 字段，不新建检索结果表。另通过迁移 `0011_web_search_quotas` 增加独立配额账本，按 UTC 日期记录全局及用户查询预占；聊天删除不重置当日配额。当独立检索审计、聚合分析或体积增长成为实际需求时，再迁到专用检索表。

## 5. 确保回答能追溯来源

模型接收经过编号的证据片段，按约定标记引用，例如 `[[source:s1]]`。链接从服务端快照解析，不能让模型生成的任意 URL 直接成为已验证来源。前端将合法标记呈现为可点击编号，流式标记尚未闭合时暂缓渲染，代码块及普通用户文本不按引用标记处理。

来源列表区分“检索到的资料”和“回答实际引用的资料”，默认突出实际引用。正文结束时用相同语法规则校验引用 ID；无效标记不生成可点击链接，并在本轮记录引用异常。编号校验仅能证明映射有效，不能证明片段支持结论，事实支持程度需纳入样本验收。

历史恢复读取同一份快照。下一轮追问所使用的历史块，以及用户明确引用的历史回答，应有限附带已引用来源的标题、URL、编号和时间，而不是反复注入网页全文。摘要保留“截至何时、依据什么来源”的限定；网页来源标识与现有摘要的 `source_message_ids` 分开，后者仍只代表数据库消息。

摘要增加独立的 `web_references` 数组，每项包含 `message_id`、`source_id`、`retrieved_at`；标题和 URL 从当前用户可访问的原消息来源快照解析。后端验证引用是本次摘要输入来源集合的子集，时间与保存快照一致。没有网页引用时数组为空，继续沿用内容版本失效与受保护写回规则。

中断或失败回答同样需要解析已保存部分正文中的合法引用。允许保存检查点时，部分正文与引用集合一起保存；取消后不得通过额外无条件写回补齐元数据。恢复时可依据已持久化正文和候选来源快照重算引用，不能引用只在客户端收到、尚未保存的尾部内容。

联网关闭意味着不发起新的搜索；本会话已经存在的来源仍可用于解释历史回答，但不能宣称已重新核实。用户问“现在是否仍成立”且联网关闭时，需要说明时效限制。

## 6. 保持取消、幂等和重新生成一致

| 操作或异常            | 必须保持的行为                                                             |
| --------------------- | -------------------------------------------------------------------------- |
| 同请求 ID、同参数重试 | 运行中返回已有运行状态；已结束时重放保存结果，不重新决策或搜索             |
| 客户端指定联网模式    | 返回参数错误，联网策略由后端统一派生                                       |
| 获取会话所有权失败    | 不调用决策模型和搜索服务                                                   |
| 决策或搜索时停止      | 持久化取消，停止后续阶段，尽可能中止外部调用；迟到结果不得写回或显示       |
| 重新生成              | 新请求重新决策，必要时重新检索；原答案与原来源一起保留，直到新答案成功替换 |
| 重新生成失败或取消    | 沿用现有保留原答案的规则，原来源也保持有效                                 |
| 切换会话              | UI 丢弃旧 stream 的事件，后端状态只归属原会话                              |
| 进程崩溃或租约过期    | 沿用现有失败恢复规则，不在旧请求名下盲目重新发起付费调用                   |

指纹包含后端按请求类型派生的联网策略，不包含会变化的自动判断结果、服务商可用性或查询结果。自动判断及服务配置版本作为本轮快照保存；配置更新不应破坏已结束请求的重放。

当前上游调用以同步方式为主，前端 `AbortController` 不能证明上游已经停止。实施时使用可取消或有总截止时间的执行封装；若采用受限工作线程等待外部调用，数据库 Session 不跨线程共享，超时后的任务仍占用并发额度直到实际退出，防止泄漏线程和连接。

长等待通过短轮询或其他可取消等待机制检查持久取消并续租；不得等待同步调用返回后才首次检查。对于服务商不支持中止的已发请求，只能保证不再推进或写回，不能承诺撤回已经发生的服务商费用。进程崩溃时也不承诺第三方计费的严格“恰好一次”。

## 7. 控制延迟、成本与数据边界

以下是首轮实验起点，均应可配置，不是已达到的性能承诺。

| 项目       | 初始建议                                             | 调整依据                                             |
| ---------- | ---------------------------------------------------- | ---------------------------------------------------- |
| 决策输入   | 当前问题、必要引用及最近 1–2 轮，设置独立 token 上限 | 指代准确率与模型窗口；超预算不能静默截断问题主体     |
| 决策等待   | 总预算约 5 秒，首期默认不额外修复                    | 自定义模型延迟；失败进入明确降级                     |
| 搜索规模   | 最多两个查询，去重后最多五条来源                     | 覆盖率、支持结论的证据数与费用                       |
| 搜索等待   | 一批查询总预算约 8 秒                                | 并发上限和服务实际耗时；有部分可用结果时可使用并提示 |
| 检索证据   | 总量初始上限约 4,000 token，并受当前模型剩余容量限制 | 答案质量与上下文占用                                 |
| HTTP 连接  | 复用连接池，限制并发及响应体大小                     | 同时请求数、连接池等待、工作线程占用                 |
| 缓存       | 首期依赖请求重放，暂不做跨用户查询缓存               | 后续依据时效需求引入短期缓存，记录缓存时间           |
| 限流和额度 | 按用户及服务商配置请求速率、并发和费用上限           | 部署规模、额度及真实 usage                           |

外部调用的总截止时间应覆盖排队、连接、读取及允许的修复；不能只配置单次读超时后把它当成整轮耗时上限。两条查询可在有界并发下执行，共享一批截止时间，不串行累计两份完整超时。

现有聊天速率限制继续生效。搜索查询数由数据库原子预占，默认每用户每天 100 次、全局每天 1,000 次；相同请求不重复预占，任一级额度不足则整批回滚。预占与消息标记在受租约保护的同一事务提交，取消、超时后不退额度，因为外部服务可能已经计费。这限制的是查询数，并非包含决策及回答模型费用的货币上限。费用观测区分决策模型、搜索服务及回答模型，未知 usage 标记为未知，不把估算记为账单。

证据与系统指令分离，网页片段作为不可信参考数据，不执行其中要求更改规则、发起额外请求或泄露资料的内容。搜索服务只接收必要查询，不上传整段对话、学习记忆或凭据。用户资料中的秘密不应被提取进查询或普通日志。

首期由后端访问配置好的搜索 API，不直接抓取任意结果 URL。来源链接仅允许安全的 HTTP(S) 地址；来源标题按文本渲染，Markdown HTML 做净化。净化时同步改造现有代码复制按钮的内联事件，保留复制功能和代码高亮。以后增加网页读取时，再实施重定向逐跳校验、内网地址限制、响应大小及正文提取限制。

建议观测：决策耗时、搜索耗时、总首字延迟、搜索触发率、搜索错误率、引用异常率、证据 token、阶段取消耗时、各阶段 usage。普通日志保留请求标识、状态和统计，不记录网页全文或原始用户输入。

## 8. 定义失败后的用户体验

| 情况                             | 建议错误码                  | 后续行为                                                           |
| -------------------------------- | --------------------------- | ------------------------------------------------------------------ |
| 决策超时或结构不合法             | `WEB_DECISION_FAILED`       | 记录未完成判断，按已有知识回答并说明未联网；对时效要求不声称已核实 |
| 搜索无可用结果                   | `WEB_NO_RESULTS`            | 说明未找到足够资料，可回答稳定背景知识，保留待核实部分             |
| 搜索超时或服务异常               | `WEB_SEARCH_FAILED`         | 有可用片段则明确使用部分结果；没有则按未联网处理                   |
| 搜索额度耗尽                     | `WEB_QUOTA_EXCEEDED`        | 明确联网不可用，不通过无界重试绕过额度                             |
| 服务未配置或关闭                 | `WEB_UNAVAILABLE`           | 展示不可用状态，继续受控的普通回答                                 |
| 上下文容量不足、片段被裁剪       | `WEB_EVIDENCE_INSUFFICIENT` | 提示证据不完整；事实支持程度仍依赖回答约束及效果评估               |
| 仅要求读取 URL 全文              | `WEB_URL_FETCH_UNSUPPORTED` | 明确首期只支持检索片段，不能冒充阅读全文                           |
| 回答引用不存在的来源 ID          | `WEB_CITATION_INVALID`      | 禁用无效引用链接，保存告警及异常计数                               |
| 用户取消、内容版本改变、租约丢失 | 沿用现有聊天错误码          | 结束本轮，不降级成普通回答继续运行                                 |
| 最终回答失败                     | 沿用现有模型错误码          | 保存已有合法状态和部分内容，按现有重试规则处理                     |

是否依赖最新事实不能只依赖失败的决策结果。没有可用证据时，服务端提示明确本轮未取得可用联网证据，让回答模型保留用户原问题的时效限制；前端提示与正文都不能显示“已联网核实”。只有部分证据可用时，明确资料不完整，允许引用实际取得的有效片段；只对被证据支持的结论作答，对其余结论保留未核实限定。

单元与契约测试使用隔离数据库和模型、搜索替身；真实 Provider 评估单独执行并限制额度，避免日常测试依赖付费网络。

建议采用以下初始启用门槛，并在首次评估前冻结样本、模型配置和阈值；这些数值是本方案的建议目标，尚未实测：

- 决策集至少 60 条人工标注的中文问题，包含 20 条稳定知识、20 条明确需要外部最新事实、10 条指代追问和 10 条资料范围限制；外部最新事实漏检索率不超过 5%，稳定知识误检索率不超过 10%。
- 关闭模式的决策和搜索调用数为零，用户明确限定已有材料的用例搜索数为零；取消、隔离、幂等、合法来源映射等确定性契约测试全部通过。
- 抽检至少 20 条联网回答，对引用所支撑的事实逐项评审，支持率不低于 90%；不得出现伪造来源或将未核实的最新事实声称为已核实。少量样本通过不代表总体准确率，启用后继续记录异常。
- 在固定模型与并发条件下，对自动但未搜索的请求，首字延迟相对关闭模式的增量 P95 初始目标不超过 5 秒；联网准备阶段 P95 初始目标不超过 15 秒。同时记录超时及降级比例，决策或搜索阶段因超时降级的请求占比初始目标不超过 5%，避免靠频繁降级换取低延迟。

未通过时保持受限验证，调整预算、模型或 Provider 后重新评估；阈值调整须记录原因，不能仅因已有结果不达标就直接视为通过。未记录真实质量、延迟和费用结果，只能认定工程联调完成，不能认定具备启用条件。
